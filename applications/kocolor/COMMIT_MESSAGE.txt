Align CapabilityRouter Execution Order and Settings UI Status with Application Architecture

This commit aligns the AI provider execution order and the Settings UI status display with the codebase logic.

Summary of Changes:
1. **Capability Router Execution Order (`CapabilityRouterImpl.kt`)**: Re-ordered provider resolution to match the architectural pipeline:
   - Priority 1: BYOK Cloud AI (if user configures a custom Gemini API Key).
   - Priority 2: On-Device Local AI (Gemini Nano).
   - Priority 3: Enterprise Security / Firebase AI Logic (Managed Cloud Fallback, if enabled).
2. **BYOK Provider State (`ByokAiProvider.kt`)**: Implemented API key configuration setter and availability check based on custom key presence.
3. **Settings Status Header (`AiConfigurationCard.kt`)**: Updated `statusText` calculation in the Settings UI to reflect active provider hierarchy accurately:
   - Displays "On (BYOK - Gemini Key)" when a key is configured.
   - Displays "On (Local AI)" when executing on-device.
   - Displays "On (Enterprise Firebase)" when using the managed cloud fallback.
   - Displays "Off (AI Features Disabled)" or "Off (No Active Provider)" when disabled.
