The Android XR Hardware & Software Matrix

In the Android XR ecosystem, the entire development paradigm boils down to a simple decision matrix. If you know how many displays the user is looking at and where the CPU is located, the hardware category and the required software libraries define themselves.

Number of Screens Where is the Main Compute? Hardware Category UI Toolkit & Core SDK
0 (Audio-Only) Host Phone (Pocket) AI Glasses
(e.g., Jinju)		 Voice / TTS + Jetpack Projected
(Bypass UI rendering entirely)
1 (Monocular) Host Phone (Pocket) AI Glasses

2 (Binocular) Compute Puck (Tethered) Wired XR Glasses
(e.g., XREAL AURA)		 Jetpack Compose for XR + SceneCore / ARCore
2 (Binocular) On-Device (Face) XR Headset
(e.g., Galaxy XR)		 Jetpack Compose for XR + SceneCore / ARCore

How to Read the Matrix as a Developer:

  1. The Screen Rule: If the answer is 1, you are dealing with additive light and extreme thermal limits. You must use Glimmer. If the answer is 2, you are dealing with stereoscopic 3D and immersive canvases. You use Compose for XR.
  2. The Compute Rule: If the compute is on the Phone, you must manage a projection tether (Jetpack Projected) and build "disconnection-proof" lifecycle logic. If the compute is in a Puck or On-Device, your application runs natively like a standard VR/spatial app.
