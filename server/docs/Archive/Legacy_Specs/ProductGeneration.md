# KoColor Engineering Docs: Image Optimization Pipeline (Phase 2)

## Executive Summary: The Pivot to "Compute-at-Compile-Time"

Phase 2 of the KoColor CDN architecture represents a fundamental pivot away from fragile, "single-grid" asset strategies toward a robust, "data-driven individual asset" strategy.

While our Phase 1 uniform 3x3 grid proposal was elegant, it introduced unsustainable complexity due to diffusion model inconsistencies regarding precise text rendering and alignment across multiple objects. Strict validation would require advanced AI-driven spatial detection, slowing the build boundary.

We have adopted the optimized, industry-standard **"Compute-at-Compile-Time" (CCT) strategy**.

### The CCT Philosophy

In this architecture, we utilize powerful development hardware (e.g., M2 Pro) to execute computationally expensive optimization logic *before* assets are committed to the CDN.

We sacrifice CPU cycles during the build phase to ruthlessly save GPU memory and bandwidth on the mobile user's device. We perform lossy WebP conversion, generate distinct hero/thumbnail streams, and create Base83 BlurHash placeholders all at compile time. This ensures a zero-latency, high-performance visual experience in Jetpack Compose, regardless of the user's network speed.

## Step 2: Asset Optimization (The Rust Compiler)

Once the raw high-fidelity inputs are drop-committed to the `./raw_assets/` directory, the Rust tool must be executed to complete the transformation.

This tool utilizes the power of **Rayon** for concurrent folder processing, blasting through all raw assets simultaneously to create a two-stream optimized output:

### Stream A: High-Fidelity Hero Assets (Detail Screen)

* **Input:** Raw High-Res PNG (1:1 Ratio).
* **Processing:**
* **Image Format:** Switch to optimized Lossy **WebP (Quality 85%)**.
* **Compression:** Swapping lossless (PNG) for lossy (WebP) dramatically accelerates network fetch times on the mobile client.
* **Branding:** Requires the larger, high-accuracy KoColor branding typography generated by Gemini.
* **Resolution:** 1024x1024.


* **Result:** A pristine detailed image for the product detail screen.

### Stream B: Performance Thumbnail Assets (Scrolling Grids)

* **Input:** High-Fidelity Hero (WebP).
* **Processing:**
* **Resolution:** Downscaled precisely to 256x256.
* **Format:** Optimized WebP to ensure maximum concurrent render speeds during high-velocity scrolling.
* **BlurHash Generation:** This asset is the final input for the Rust BlurHash generator, which encodes it into the stable Base83 string that is injected into the production JSON.


* **Result:** The foundational asset for fast LazyGrid rendering.

### Implementation Checklist

To ensure a successful pipeline execution on your builder machine, complete this checklist:

1. Add the necessary crates to your `Cargo.toml`: `image`, `rayon`, `blurhash`, `std`, `path`.
2. Populate your `./raw_assets/` folder with all 9 Gemini-generated PNGs.
3. Implement the specialized Rust code (or the simplified grid logic, depending on requirements) in `src/main.rs`.
4. Execute the pipeline with `cargo run --release`. Always use `--release` for computationally heavy image processing math to activate compiler optimizations.
