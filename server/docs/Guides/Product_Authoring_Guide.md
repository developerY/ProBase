# KCPS Product Authoring Guide

This guide explains how to define products in the source JSON format used by the KoColor Normalization Compiler to generate compliant `.kpkg` distribution artifacts.

## 🏗️ Architecture Overview

The KoColor ecosystem follows a data-driven, Hub-and-Spoke model where the Android Phone acts as the central intelligence hub for downstream Wear OS and XR devices.

## 📦 Creating a Product Package from JSON

All source data should be structured as a `StarterPackResponse`. JSON is the authoritative product input for the system.

```json
{
  "schema_version": 1,
  "cosmetics": [ ... ],
  "clothing": [ ... ]
}
```

## ✅ Package Author Checklist

To ensure your package passes verification and provides a high-quality user experience:

1.  **Strict Uppercase**: All category and facet values (Enums) MUST be strictly uppercase (e.g., `LIPS`, `STICK`).
2.  **HTTPS Only**: All image and thumbnail URLs MUST use HTTPS.
3.  **Hashed Filenames**: When deploying, always use the content-addressed name generated by the compiler (`<id>-<sha256>.kpkg`).
4.  **No Null Values in Arrays**: Arrays (like `ingredients`) must not contain null elements.
5.  **ID Uniqueness**: Ensure every product ID is globally unique within your organization.

## Appendix: Authoring Principle

Product data is **data, not Rust source code**.

New products and partner packages MUST be provided as JSON conforming to KCPS v1. The KoColor Normalization Compiler is data-driven and MUST NOT require Rust source-code changes when new products, brands, categories, or packages are introduced.

The compiler is responsible for:
1. Parsing the source JSON.
2. Validating the data against KCPS v1.
3. Normalizing and canonicalizing the data.
4. Computing compiler-derived attributes where applicable.
5. Generating the canonical payload.
6. Compressing the payload with Zstandard.
7. Computing the package hash (SHA-256).
8. Signing the package with Ed25519.
9. Producing the final `.kpkg` artifact and manifest metadata.

Therefore, adding a new product or partner package requires only new JSON input; it MUST NOT require modification of the compiler source code unless the KCPS specification or compiler behavior itself is intentionally being changed.
