# Implementation Plan: Rust Distribution Pipeline (`kc-distributor`)

This document outlines the implementation of the **Distribution Packager**, a dedicated Rust-native tool responsible for the final flattening, transcoding, and bundling of the KoColor CDN payloads.

---

## 🏗️ 1. Crate Architecture

We will establish a new binary crate, `kc-distributor`, that acts as the final "Deployment Orchestrator."

### Key Responsibilities:
*   **Discovery**: Recursive traversal of the hierarchical `raw_assets/` authoring directory.
*   **Transcoding**: High-performance conversion of raw PNGs into optimized WebP Hero/Thumb assets.
*   **Routing**: Flattening the authoring hierarchy into a machine-centric CDN structure.
*   **Bundling**: Generating a single, signed, and timestamped deployment `.zip`.

---

## 🗂️ 2. The CDN Schema (Output Format)

The tool will produce a flattened `dist/` directory with the following deterministic layout:

```text
dist/
├── manifest.json            # The signed root of trust
├── starter-kit.kpkg         # Signed/Compressed product data
├── assets/
│   ├── hero/                # 1024x1024 WebP high-res
│   └── thumb/               # 256x256 WebP placeholders
├── notes/                   # Flattened editorial content
└── json/                    # (Optional) Flattened raw product sources
```

---

## ⚙️ 3. Post-Processing Logic

### 🖼️ Asset Transcoding
We will utilize the `image` crate with `webp` support.
*   **Hero**: 1024x1024 Lanczos3 (Quality: 80).
*   **Thumb**: 256x256 Triangle (Quality: 60).
*   **Naming**: Assets will be keyed strictly by their product `{id}`, eliminating hierarchical complexity for the mobile client.

### 📝 Metadata Flattening
*   **Notes**: Any `{id}.notes.json` found in the hierarchy will be collected and moved to the root `/notes` directory.
*   **Packages**: Existing `.kpkg` files generated by the optimizer will be included in the root of the distribution.

---

## 📦 4. Deployment Bundling (ZIP)

The final stage compresses the entire `dist/` directory into `kocolor-v1-deploy.zip`. This ensures a single, immutable artifact can be uploaded to the edge network, preventing partial or inconsistent data states.
